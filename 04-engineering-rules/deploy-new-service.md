# Деплой нового сервиса

**Scope:** порядок действий, чтобы развернуть на сервере новый сервис StudioDesk (например, фронтенд `admin.` или `app.`) по уже работающей схеме бэкенда. Правила и устройство деплоя — `03-architecture/deployment.md`; этот документ их не меняет.

Образец — `studio-desk-backend`: `deploy/`, `.github/workflows/ci.yml`, `deploy/README.md`.

## Что выбрать до начала

Согласовать с владельцем:

- адрес из таблицы адресов в `deployment.md`;
- порт на сервере на `127.0.0.1`, не занятый другими (бэкенд — `3100`);
- имя образа `ghcr.io/igorchugurov/<repo>`;
- нужна ли сервису база и миграции;
- какие настройки сервису нужны в `.env`.

## Порядок

1. **DNS.** В Vercel добавить запись A `<адрес>` → `31.220.80.11`. Проверить через `dig @1.1.1.1` и `dig @8.8.8.8`.
2. **Файлы в репозитории.** Скопировать из бэкенда и поменять имя, порт и адрес:
   - `deploy/docker-compose.yml` — без `postgres` и `migrate`, если базы нет;
   - `deploy/deploy.sh` — без шагов базы и миграций, если базы нет; проверка — адрес здоровья сервиса;
   - `deploy/nginx/<адрес>.conf`;
   - `deploy/README.md`;
   - задание `deploy` в `.github/workflows/ci.yml`.

   Папка сервиса на сервере: `/opt/studio-desk/<сервис>/`.
3. **Проверить локально:** `docker compose config` с фиктивным `.env`, `bash -n` для скриптов, сборка образа.
4. **Ключ и секреты.** Все сервисы StudioDesk разворачиваются под одним пользователем сервера `studio-desk`, у каждого репозитория свой ключ деплоя. Агент через `gh`: новый ключ ed25519 только для этого репозитория; секреты `DEPLOY_HOST`, `DEPLOY_USER` (`studio-desk`), `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`; удалить локальный приватный ключ.
5. **Сервер, вручную под root** (команды по образцу `deploy/README.md` бэкенда):
   - публичный ключ — новой строкой в `authorized_keys` пользователя `studio-desk`;
   - папка `/opt/studio-desk/<сервис>/` и её `.env`, пароли генерируются на сервере;
   - сайт nginx, `nginx -t`, перезагрузка, `certbot --nginx -d <адрес> --redirect`;
   - сверить отпечаток сервера с `DEPLOY_KNOWN_HOSTS`.
6. **Первый деплой:** коммит и пуш в `development` по просьбе владельца, следить через `gh run watch`.
7. **Проверка:** адрес здоровья по HTTPS отвечает `200`; HTTP перенаправляет на HTTPS.

## Уроки первого деплоя

- Видимость пакета GHCR наследуется от репозитория через метку `org.opencontainers.image.source`: открытый репозиторий — открытый образ, переключать вручную не нужно.
- Команды для сервера давать без отступов: heredoc с `EOF` внутри списка с отступом ломается.
- Генерацию ключа и запись секретов через `gh` подтверждает владелец в окне одобрения.
- Номер версии из командной строки перекрывает `image.env`: старая версия остаётся записанной, пока новая не запущена.
- В первые секунды после запуска проверка здоровья получает обрыв соединения — это нормально, `deploy.sh` повторяет её.
- Сервису передаются только нужные ему настройки, а не весь `.env`: пароль суперпользователя PostgreSQL есть только у PostgreSQL.
