# Правила документации

**Scope:** документация StudioDesk в репозитории `studio-desk-docs` и её связь с репозиториями frontend и backend.

## Эссе — что это

Правила определяют, как в проекте создаётся, хранится и меняется документация: что считается правдой, где лежит каноническое знание, как устроен документ и когда его разрешено менять.

Проект ведётся от документации. Сначала утверждается описание фичи, потом на его основе формулируются задания дизайнеру, бэкенду и фронтенду. Поэтому канон должен быть единым и однозначным.

## Эссе — что считается правдой

| Вопрос | Что главнее |
|---|---|
| Как продукт должен себя вести | Утверждённый канон в этом репозитории |
| Как система работает сейчас | Код |
| Задания дизайнеру, бэкенду, фронтенду | Производные документы: объясняют канон и ссылаются на него. При расхождении побеждает канон |
| Чат, `plan.md`, `research/`, наброски | Рабочие материалы. Канон не заменяют и авторитета не имеют |

Одна тема имеет один источник правды. Остальные документы ссылаются на него и не копируют. Если два канонических документа противоречат друг другу, это расхождение канона: решаем вместе, победителя по дате не выбираем.

## Эссе — зоны

| Зона | Что лежит | Канон |
|---|---|---|
| `00-governance/` | Правила документации, сквозной процесс фичи, шаблоны заданий, правила согласования | да |
| `01-product/` | Профиль продукта, доменные темы (канон вместе с заданиями по теме: дизайнеру, бэкенду, фронтенду), пользовательские потоки | да |
| `02-design/` | Использование кита, стандарт проектирования по потокам, правила мини-сайта студии | да |
| `03-architecture/` | Сквозные технические решения: мультитенантность, вход, модули бэкенда, развёртывание | да |
| `04-engineering-rules/` | Правила бэкенда (Nest) и фронтенда (Next) | да |
| `90-operations/` | Журнал решений и открытых вопросов | нет |

У каждой зоны есть `README.md` с оглавлением. Зона появляется, когда в неё попадает первый утверждённый документ. Материал вне зон (`plan.md`, `research/`) не канон.

## Эссе — как устроен документ

Каждый документ и каждый крупный раздел: сначала короткое эссе (что это, зачем, как работает, как связано), затем блок для агента (контракты, запреты, чеклисты, критерии приёмки). Техническое сокращение не бывает единственным объяснением. В каноне лежит только утверждённое. Нерешённое оформляется явным разделом «Открытые вопросы».

## Эссе — когда документация меняется

Пока тема обсуждается, файлов нет: всё живёт в чате. Файл создаётся или правится только после утверждения темы и явного «ОК». Перед записью называются файл, раздел, что изменится и зачем. После записи показывается реальный diff. Коммит делается отдельно и только по явной просьбе. Если при реализации поведение изменилось, документ обновляется в том же цикле работы.

## Эссе — как связано

Связано с сквозным процессом фичи, шаблонами заданий и правилами согласования (в `00-governance/`, будут описаны отдельно) и с журналом решений (`90-operations/`).

## Агент — правила

| Правило | Детали |
|---|---|
| Источник правды | Канон в зонах `00`–`04`; одна тема — один документ-владелец |
| Что считается каноном | Файл в канонической зоне, записанный после явного ОК владельца |
| Расхождение | Два канона противоречат друг другу: остановиться, сообщить, решить вместе |
| Реализация | Текущее поведение берём из кода; из README или чужих заметок не выдумываем |
| Отрицательные утверждения | Указывать, где искали («не найдено в проверенных путях»), а не «этого нет» |
| Предположения | Помечать как предположение или открытый вопрос, в канон не писать как факт |
| Копирование | Не копировать один документ в другой, ставить ссылку |
| Вне зон | `plan.md`, `research/`, наброски: не канон, не переносить без отдельного согласования |

## Агент — форма документа

- Эссе, затем блок агента.
- Необязательные поля вверху: `**Scope:**`, `**Last verified:** ГГГГ-ММ-ДД`.
- Поля Status нет.
- Язык: канон (описание фичи), правила и процесс — русский; задание дизайнеру — украинский; задания бэкенду и фронтенду — английский; код, идентификаторы, пути — английский.
- В зоне есть `README.md` с таблицей документов.

## Агент — чеклист качества

- [ ] Эссе отвечает: что, зачем, как, с чем связано
- [ ] Блок агента практичен и не вводит продуктовых фактов
- [ ] Нет поля Status
- [ ] Файл лежит в разрешённой зоне
- [ ] Нет дубля другого источника правды
- [ ] Есть ссылки на связанные документы
- [ ] Нерешённое вынесено в «Открытые вопросы»
- [ ] Записан после явного ОК владельца
