# Развёртывание

**Scope:** адреса StudioDesk в интернете и как бэкенд попадает на сервер: сервер, образ, вход GitHub Actions, PostgreSQL, nginx и сертификат, шаги деплоя, серверный `.env`, разовая настройка.

## Эссе — что это

Бэкенд разворачивается автоматически: пуш в ветку `development` репозитория `studio-desk-backend` запускает GitHub Actions, который прогоняет тесты, собирает образ и обновляет бэкенд на сервере. На сервере не собирается код и не хранится репозиторий: туда попадает только готовый образ, прошедший тесты.

## Эссе — адреса

Базовый домен — `studio-desk.axondigital.xyz`. Записями DNS домена `axondigital.xyz` управляет Vercel (серверы имён `ns1/ns2.vercel-dns.com`, регистратор Namecheap). Явная запись поддомена важнее общей записи `*.axondigital.xyz`, которая ведёт на Vercel.

| Адрес | Что там | Когда |
|---|---|---|
| `api.studio-desk.axondigital.xyz` | бэкенд, все три API (`/api/platform`, `/api/studio`, `/api/public`) | сейчас |
| `admin.studio-desk.axondigital.xyz` | фронтенд админки платформы | с фронтендом админки платформы |
| `app.studio-desk.axondigital.xyz` | фронтенд админки студии | с админкой студии |
| `studio-desk.axondigital.xyz` | рекламная страница платформы | когда будет обсуждена |
| `<поддомен>.studio-desk.axondigital.xyz` | публичный сайт студии | с публичным сайтом |

Сайты студий не прописываются в DNS по одному. Одна общая запись `*.studio-desk.axondigital.xyz` ведёт все поддомены на сервер, nginx передаёт запрос приложению вместе с `Host`, и приложение определяет студию по поддомену. Общая запись и общий сертификат на все поддомены добавляются вместе с публичным сайтом: раньше запросы попадали бы в сайт nginx по умолчанию. Имена `api`, `admin`, `app`, `www` должны быть в списке зарезервированных поддоменов студий.

## Эссе — сервер

VPS `31.220.80.11`: Ubuntu 24.04, x86_64, 8 ядер, 23 ГБ памяти. Сервер общий: на нём работают другие проекты (nginx-сайты `api.oblikflow.com`, `assistant.axondigital.xyz`). StudioDesk их не трогает.

Всё StudioDesk на сервере лежит в `/opt/studio-desk/` и работает в Docker (пакет `docker.io` и `docker-compose-v2` из репозиториев Ubuntu).

## Эссе — образ

GitHub Actions собирает образ по `Dockerfile` и публикует в GitHub Container Registry: `ghcr.io/igorchugurov/studio-desk-backend` с метками номера коммита и `development`. Образ открытый: код и так в открытом репозитории, секретов в образе нет, а серверу не нужен токен для скачивания. Пакет связан с репозиторием меткой `org.opencontainers.image.source` и наследует его видимость, ручных действий не нужно.

## Эссе — вход GitHub Actions на сервер

GitHub Actions входит на сервер по SSH под отдельным пользователем `studio-desk`: без пароля, только по ключу, владеет только `/opt/studio-desk/`, состоит в группе `docker`. Ключ создаётся только для деплоя этого репозитория: публичная половина лежит на сервере, приватная — только в секретах репозитория на GitHub.

Секреты репозитория `studio-desk-backend`: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` (отпечаток сервера, чтобы не подключиться к подставному).

Группа `docker` на практике даёт права, близкие к `root`. Отдельный пользователь защищает от случайных действий вне `/opt/studio-desk/`, от входа по паролю и отделяет ключ деплоя от личного доступа, но не изолирует полностью. Ключ не ограничен одним скриптом (см. «Открытые вопросы»).

## Эссе — PostgreSQL на сервере

PostgreSQL 18 в контейнере, в том же `docker-compose.yml`, что и бэкенд. Порт базы наружу не выводится: бэкенд обращается к ней по внутренней сети Docker. Данные хранятся в отдельном томе Docker и переживают перезапуск и обновление контейнеров. Пользователей и базу создаёт тот же стартовый скрипт, что и локально, при первом запуске пустой базы; тестовая база на сервере не создаётся. Доступ к базе с Mac — через SSH-туннель.

## Эссе — nginx и сертификат

Контейнер бэкенда открывает порт только внутри сервера: `127.0.0.1:3100`. Снаружи запросы приходят через существующий nginx: отдельный файл сайта `/etc/nginx/sites-available/api.studio-desk.axondigital.xyz` передаёт их на `127.0.0.1:3100` вместе с `Host` и IP клиента. Сертификат выпускается certbot (`--nginx`), продлевается существующим `certbot.timer`. Перед каждой перезагрузкой nginx выполняется `nginx -t`. nginx настраивается вручную под `root`; GitHub Actions его не трогает.

## Эссе — шаги деплоя

При пуше в `development`:

1. Тесты (тот же workflow, что и без деплоя). Красные тесты — деплоя нет.
2. Сборка образа и публикация в GHCR.
3. Копирование `docker-compose.yml` и стартового скрипта из папки `deploy/` репозитория в `/opt/studio-desk/`.
4. На сервере: скачать образ; убедиться, что PostgreSQL запущен; выполнить миграции одноразовым контейнером из нового образа под `studio_desk_owner` — если миграции упали, деплой останавливается и работает старая версия; перезапустить бэкенд; проверять `/api/health` около 30 секунд — без `200` задание в GitHub красное.
5. Номер развёрнутой версии записывается в файл в `/opt/studio-desk/`, чтобы ручной перезапуск и перезагрузка сервера поднимали ту же версию.

Деплои не пересекаются: следующий ждёт предыдущий. Контейнеры перезапускаются сами после перезагрузки сервера (`unless-stopped`). При перезапуске бэкенда возможен простой в несколько секунд.

Откат — запуск предыдущего номера образа. Миграции назад не откатываются: старый код должен работать с новой схемой.

На сервере `APP_ENV=production`, документация OpenAPI выключена (см. `api-conventions.md`).

## Эссе — серверный `.env` и разовая настройка

`/opt/studio-desk/.env` создаётся вручную один раз на сервере, права только у `studio-desk`. Значения: `APP_ENV=production`, `PORT=3000` (внутри контейнера), `DB_HOST=postgres`, `DB_PORT=5432`, `DB_NAME=studio_desk`; пять паролей генерируются случайно на самом сервере и не проходят через чат или Mac.

Разовая настройка до первого деплоя: установить `docker-compose-v2`; создать пользователя `studio-desk`; создать `/opt/studio-desk/` и `.env`; настроить сайт nginx и выпустить сертификат; создать ключ деплоя и секреты GitHub.

## Агент — запреты

- Менять чужие сайты nginx, `default`, процессы и файлы вне `/opt/studio-desk/`.
- Перезагружать nginx без успешного `nginx -t`.
- Выводить порт PostgreSQL наружу; открывать порт бэкенда не на `127.0.0.1`.
- Класть секреты в репозиторий, образ, логи GitHub Actions или чат.
- Деплоить мимо тестов.
- Перезапускать бэкенд, если миграции не прошли.
- Удалять том данных PostgreSQL на сервере.

## Агент — чеклист изменения деплоя

- [ ] Изменения `deploy/` и workflow проходят через Git
- [ ] Новые настройки добавлены в серверный `.env` до деплоя
- [ ] После деплоя `/api/health` отвечает `200` через `https://api.studio-desk.axondigital.xyz/api/health`

## Открытые вопросы

- Резервные копии базы.
- Ограничение ключа деплоя одним скриптом.
- Общая запись DNS и общий сертификат для сайтов студий (вместе с публичным сайтом).
