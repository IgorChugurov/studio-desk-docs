# Поля каталога для расписания

## Цель

Добавить в API каталога админки студии поля, без которых нельзя хранить занятие. Задание — `01-product/studio-admin/catalogs-schedule-fields-backend-brief.md`. Канон — `01-product/studio-admin/catalogs.md`.

Поля: тип и часовой пояс зала, длительность вида занятия по умолчанию, связь «тренер — вид занятия». Сначала расширение `catalogs-api-contract.md`. Код и миграция начинаются после согласия владельца на контракт и на структуру колонок и таблицы связи.

## Границы

- Расписание не начинается: ни занятия, ни шаблоны, ни действия с неделями, ни сетка на страницах зала и тренера. Это `schedule-backend-brief.md`.
- Смена пояса зала в этой задаче только сохраняет новый пояс. Проверки «у тренера два занятия сразу» нет: занятий ещё нет.
- Вместимость, «группа или один человек», цена, удаление зала, тренера и вида занятия не входят.
- Роль сотрудника «тренер» и её связь с карточкой каталога не входят.
- Уже сделанные залы, тренеры и виды занятий, кроме новых полей, остаются как есть. Старым залам проставляется тип «обычный» и пояс их студии. Старым видам проставляется длительность 60.

## Этап

`feature-workflow.md`, полный маршрут, этап 5 — задание бэкенду. Ведёт бэкенд. Фазы — в задании. Фазы 2 и 3 друг от друга не зависят. Сейчас фаза 1, контракт не начат.

Агент, который берёт эту запись, работает так:

1. Читает задание, канон `catalogs.md`, действующий `catalogs-api-contract.md`, `03-architecture/api-conventions.md`, `03-architecture/backend-structure.md`, `04-engineering-rules/backend.md`. Поведение берёт из задания. Где задание и канон расходятся, останавливается и спрашивает владельца. Сам не выбирает.
2. Фаза 1: дописывает `01-product/studio-admin/catalogs-api-contract.md` и показывает diff. Дальше не идёт, пока владелец не согласился на контракт.
3. До миграции показывает владельцу структуру новых колонок и таблицы связи и ждёт согласия. Таблицы не создаёт раньше этого согласия.
4. План реализации показывает с четырьмя ответами: причина, что уже есть и можно переиспользовать, обратная совместимость, зона влияния. Код пишет после согласия на план.
5. После кода показывает реальный diff. Отклонения, решения бэкенда и правки документов записывает в `catalogs-schedule-fields-backend-brief-feedback.md`. Задание и канон не правит.
6. Прогоняет тесты из задания, включая тест прав на новые таблицы. Коммит и пуш только по явной просьбе владельца. В сообщение коммита входит `2026-10-14-studio-admin-catalogs-schedule-fields`.
