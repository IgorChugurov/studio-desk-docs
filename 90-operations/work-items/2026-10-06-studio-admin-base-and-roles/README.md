# Админка студии — основа и роли

## Цель

Обсудить и согласовать темы A и B админки студии вместе. A — основа: вход владельца и сотрудников, страница для «Log in as studio», навбар, первый вход и настройки студии (язык, страна, валюта, часовой пояс). B — роли и доступ: кто есть в студии, что видит, как управляются сотрудники. Нужна минимально необходимая модель без лишней сложности, с опорой на анализ рынка (`research/`) и подход gmall (список разделов, доступ по выбранным разделам на фронтенде и на бэкенде). Модель должна покрывать случаи: сотрудник только с расписанием, управляющий контентом, бухгалтер с отчётами, тренер, который управляет только своими занятиями.

## Границы

- Каталоги, расписание, клиенты и записи, абонементы, учёт — отдельные темы (C–G), не эта.
- Публичный сайт студии и вход клиентов — не эта задача.
- Решения принимает владелец; предложения не записываются в канон без его «ОК».
- Файлы канона создаём только после согласования темы.
- Роль «тренер» и связь с каталогом тренеров в задание бэкенду не вошли.
