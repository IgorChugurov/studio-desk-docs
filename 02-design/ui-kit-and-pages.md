# Дизайн-кит, токены, компоненты и вёрстка страниц

**Scope:** как устроена визуальная система в `studio-desk-frontend`: токены, типографика, каталог компонентов `src/shared/ui/`, типы страниц, владелец скролла, карта экрана перед кодом и матрица состояний. Относится к админке платформы (`/platform`) и админке организации (`/studio`).
**Last verified:** 2026-11-05

## Эссе — что это

В `studio-desk-frontend` перенесён дизайн-кит (токены, шрифты, типографика и базовые компоненты) как собственный исходный код проекта в `src/shared/styles/` и `src/shared/ui/`. Общего внешнего пакета и конфигурационных движков нет.

Этот документ — единое правило того, из каких кирпичей и по каким правилам собирается любой экран во фронтенде: как тогда, когда экран делается напрямую по разделу «Потоки по шагам» канона темы (без Figma), так и тогда, когда по теме есть макеты в Figma.

## Эссе — зачем

Без явного описания кита и типов страниц агент при вёрстке нового экрана начинает писать сырые `<button>`, `<input>`, `<table>` с произвольными классами Tailwind, подбирать цвета и отступы «на глаз», ломать скролл страницы или пропускать состояния ошибки, загрузки и пустого списка.

Когда все экраны собираются строго из `src/shared/ui/`, токенов `figma-tokens.css` и четырёх эталонных типов поверхностей, интерфейс остаётся цельным и предсказуемым даже без отдельного макета Figma на каждый шаг.

## Эссе — как это работает

Любая работа над экраном или визуальным компонентом идёт в четыре шага:

1. **Выбор типа поверхности и владельца скролла** (каркас `AppShell`, страница списка, страница формы/редактирования, модальное окно).
2. **Карта экрана (Screen mapping) до написания кода:** каждый блок потока из канона темы (или фрейма Figma, когда он есть) сопоставляется с готовым компонентом из `src/shared/ui/`, токенами и нужными состояниями. Никакой UI-код не пишется до «ОК» владельца на карту экрана и план среза.
3. **Сборка из `src/shared/ui/` и токенов:** используются только существующие компоненты кита, семантические переменные `--background-*`, `--text-*`, `--border-*`, `--icons-*`, шкала `--space-*`, `--radius-*` и классы типографики `.figma-*`.
4. **Самопроверка перед сдачей:** проверка всех состояний из матрицы, владельца скролла, мобильной версии (`390×844`), при наличии Figma — таблица сверки свойств Inspect, и обязательный прогон `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`.

## Агент — токены (`src/shared/styles/figma-tokens.css`)

Все отступы, радиусы, цвета и размеры иконок берутся из CSS-переменных в `src/shared/styles/figma-tokens.css`. Не выдумывать произвольные `px` или hex-цвета, когда есть токен.

### Отступы (`--space-*`, сетка 8px с малым шагом 2px/4px)

| Токен | Значение | Типичное применение |
|---|---|---|
| `--space-0` | `0` | сброс отступа |
| `--space-050` | `2px` | микро-интервал |
| `--space-100` | `4px` | заголовок ↔ подпись поля, малая иконка-кнопка (`sm`) |
| `--space-150` | `6px` | плотные бейджи и теги |
| `--space-200` | `8px` | иконка ↔ текст в кнопке, внутренний отступ кнопки `md` |
| `--space-250` | `10px` | вертикальный отступ кнопки `lg` |
| `--space-300` | `12px` | ячейки таблицы по вертикали, шаг между полями в модалке, футер модалки |
| `--space-400` | `16px` | базовый внутренний отступ карточек, ячеек таблицы по горизонтали, панелей |
| `--space-500` | `20px` | средний разделительный отступ |
| `--space-600` | `24px` | отступы секций страницы, шапки и тела модального окна |
| `--space-800` | `32px` | крупные отступы между блоками страницы |
| `--space-1000` .. `--space-1600` | `40px` .. `64px` | внешние отступы крупных экранов (например, экран входа) |

### Скругления (`--radius-*`) и обводки

| Токен | Значение | Где используется |
|---|---|---|
| `--radius-100` | `4px` | малые кнопки (`sm = 24px`), `icon-tertiary` |
| `--radius-150` | `6px` | внутренние элементы и теги |
| `--radius-200` | `8px` | стандартные кнопки (`md = 32px`, `lg = 40px`), поля ввода, селекты, карточки |
| `--radius-400` | `16px` | модальные окна (`Modal`), крупные контейнеры |
| `--radius-full` | `9999px` | круглые элементы (`Avatar`, счётчики) |
| `--stroke-border` | `1px` | стандартная рамка таблиц, полей, карточек |

### Семантические цвета

В компонентах экранов используются **только семантические переменные** (не палитра `--gray-*` / `--primary-light-*` напрямую и не сырые hex):

- **Фон:** `--background-gray-default` (белый фон карточек, таблиц, модалок, инпутов), `--background-gray-secondary` (фон `body`, шапки модалки, подложек), `--background-gray-tertiary`, `--background-primary-default` (основной синий CTA), `--background-primary-default-hover`, `--background-primary-default-pressed`, `--background-primary-secondary` (подсветка строки таблицы при наведении), `--background-error-default`, `--background-error-secondary`, `--background-success-default`, `--background-warning-default`, `--background-info-default`.
- **Текст:** `--text-gray-default` (основной текст), `--text-gray-secondary` (подписи, вторичный текст, заголовки колонок), `--text-gray-default-disabled` (неактивный текст), `--text-primary-default`, `--text-primary-on-primary` (белый текст на синем/красном фоне), `--text-error-default` (ошибки валидации), `--text-success-default`, `--text-warning-default`, `--text-info-default`.
- **Рамки:** `--border-gray-default` (разделители таблиц, модалок, инпутов), `--border-gray-secondary` (hover), `--border-gray-tertiary` (active/focus), `--border-primary-default`, `--border-error-default`, `--border-success-default`, `--border-info-default`.
- **Иконки:** `--icons-gray-default`, `--icons-gray-secondary`, `--icons-gray-default-disabled`, `--icons-primary-default`, `--icons-primary-on-primary`, `--icons-error-default`, `--icons-success-default`, `--icons-warning-default`.

## Агент — типографика (`src/shared/styles/figma-typography.css`)

Шрифты подключены через `next/font` в корневом layout (`globals.css`): `--headings-font` (`General Sans`), `--body-font` (`Inter`), `--mono-font` (`Roboto Mono`).

| Класс | Шрифт и размер | Особенность и где применять |
|---|---|---|
| `.figma-heading-h1` | General Sans, `40px`, Semibold (`600`), LH `120%` | Крупный заголовок героя / экрана входа |
| `.figma-heading-h2` | General Sans, `24px`, Medium (`500`), LH `120%` | Заголовок страницы или крупного раздела |
| `.figma-heading-h3` | General Sans, `20px`, Medium (`500`), LH `120%` | Заголовок модального окна, карточки или секции |
| `.figma-body-s-regular` / `.figma-body-s-medium` | Inter, `12px`, `400` / `500`, LH `115%` | **Однострочный** (`nowrap` + `ellipsis`): мелкие подписи, бейджи, компактные кнопки |
| `.figma-body-m-regular` / `.figma-body-m-medium` | Inter, `14px`, `400` / `500`, LH `115%` | **Однострочный** (`nowrap` + `ellipsis`): ячейки таблиц, поля ввода, стандартные кнопки `md` |
| `.figma-body-l-regular` / `.figma-body-l-medium` / `.figma-body-l-bold` | Inter, `16px`, `400` / `500` / `700` | **Однострочный** (`nowrap` + `ellipsis`): подзаголовки карточек, крупные кнопки `lg` |
| `.figma-body-s-multiline` / `.figma-body-m-multiline` | Inter, `12px` / `14px`, Regular (`400`), LH `140%` | **Многострочный** (без обрезки `nowrap`): пояснения под заголовками, тексты внутри модальных окон, пустые состояния, описания и ошибки |
| `.figma-mono-s-regular` / `.figma-mono-s-medium` | Roboto Mono, `12px`, `400` / `500`, LH `100%` | `.figma-mono-s-medium` — **заголовки колонок таблиц (`TableHead`)** |
| `.figma-mono-m-regular` | Roboto Mono, `14px`, `400`, LH `100%` | Даты, время, коды и технические идентификаторы в таблицах |

**Важное правило:** все однострочные классы `.figma-body-s/m/l-*` содержат `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. Для любого текста, который должен переноситься по строкам (абзацы, пояснения секций, сообщения в модалке, подсказки), использовать `.figma-body-s-multiline` или `.figma-body-m-multiline`.

- Запрещено копировать в проект сырой сгенерированный код из Figma MCP / Tailwind-генераторов как готовый UI: он служит только структурной подсказкой, а сам экран собирается на компонентах `src/shared/ui/` и токенах `figma-tokens.css`.
- Если для новой задачи действительно не хватает базового компонента в `src/shared/ui/`, агент не создаёт его молча, а явно выносит в план среза и ждёт «ОК» владельца.

## Агент — типы страниц и владелец скролла (Page types & Scroll owner)

Перед созданием или правкой любого экрана агент обязан определить его тип и сохранить эталонного владельца скролла. Двойной вертикальный скролл или скролл всего окна браузера на страницах со списками запрещён.

### 1. Каркас приложения (`AppShell`)
- **Эталон в коде:** `src/platform/shell/app-shell.tsx`, `src/studio/shell/app-shell.tsx`.
- **Устройство:** корневой контейнер `flex h-dvh flex-col` (ровно в высоту экрана браузера). Сверху закреплены `Navbar` и строка `Tabs`. Ниже — `<main className="flex min-h-0 flex-1 flex-col">{children}</main>`.
- **Правило скролла:** сам `AppShell` и `window` не скроллятся; `min-h-0 flex-1` передаёт ограниченную высоту дочерней странице.

### 2. Страница списка (`list-page`)
- **Эталон в коде:** `src/platform/studios/studios-list.tsx`, `src/studio/catalogs/resource-list.tsx`, `src/studio/staff/staff-list.tsx`.
- **Устройство:**
  1. Панель действий сверху: слева поиск (`SearchInput`) и фильтры (`FilterMenu` / `Select`), справа основная кнопка создания (`Button variant="cta"`). Все элементы панели выровнены по вертикали по центру и имеют одинаковую высоту.
  2. Контейнер таблицы: занимает всю оставшуюся высоту (`min-h-0 flex-1 overflow-auto`), таблица растянута на всю ширину (`w-full`).
  3. Под таблицей — `Pagination` (прибита к низу области контента, не уезжает внутрь скролла таблицы).
- **Владелец скролла:** внутренний скролл-контейнер вокруг `Table` (`overflow-auto`). Заголовок `TableHeader` остаётся закреплённым сверху (`sticky top-0`).
- **Мобильная версия (`390×844`):** таблица не перестраивается в карточки и колонки не выбрасываются — у контейнера таблицы работает горизонтальный скролл (`flow-design.md`).

### 3. Страница создания / редактирования / настроек (`form-page`)
- **Эталон в коде:** `src/platform/studios/studio-page.tsx`, `src/studio/catalogs/resource-form.tsx`, `src/studio/settings/settings-form.tsx`.
- **Устройство:** корневой контейнер страницы внутри `<main>` имеет `flex-1 overflow-y-auto`. Внутри — карточка/блоки полей `Field`, кнопки `Back` и `Save` / `Update`, а на страницах редактирования при необходимости дополнительные блоки ниже (галерея файлов `showcase`, встроенная недельная сетка расписания `Schedule`).
- **Владелец скролла:** контейнер самой страницы (`overflow-y-auto`).
- **Мобильная версия (`390×844`):** все поля ввода располагаются строго одно под другим в один столбец (`flow-design.md`).

### 4. Модальное окно (`modal-dialog`)
- **Эталон в коде:** `src/shared/ui/modal.tsx`, `src/studio/staff/remove-staff-dialog.tsx`, `src/studio/schedule/slot-window.tsx`.
- **Устройство:** используется компонент `Modal` (`max-h-[calc(100dvh-32px)] w-[calc(100vw-32px)] max-w-[480px]`). Шапка и футер зафиксированы, скроллится только центральный блок содержимого (`overflow-y-auto`).
- **Кнопки в футере:** передаются в порядке `Cancel`, затем основное действие (`Save` / `Confirm` / `Remove`). На десктопе они стоят в ряд справа (`sm:flex-row sm:justify-end`), на мобильном — во всю ширину одна под другой, причём основная кнопка оказывается сверху (`flex-col-reverse`).

## Агент — процесс вёрстки: Карта экрана (Screen mapping) и Матрица состояний

### Шаг 1. Карта экрана перед кодом (обязательно до «ОК»)

Независимо от того, верстается ли экран по текстовому разделу «Потоки по шагам» (без Figma) или по макету Figma, перед написанием UI-кода агент показывает владельцу короткую **Карту экрана** (вместе с 6-пунктным планом среза) и ждёт «ОК»:

1. **Поверхность и поток:** какая поверхность из `01-product/profile.md` (админка платформы или админка организации), какой раздел и какой поток из канона темы. Фигмы сейчас нет: раскладка берётся из уже собранной страницы того же типа в этом документе. `Figma node ID` пишется только если макет есть. Реестр id поверхностей не заводится.
2. **Тип страницы и владелец скролла:** `list-page` / `form-page` / `modal-dialog` / встраиваемый блок (например, сетка `Schedule`), и какой элемент держит `overflow-auto`.
3. **Таблица компонентов:** каждый блок экрана → какой компонент из `src/shared/ui/` (или локальный блок с обоснованием) → какие состояния покрываются.
4. **Отличия или новые примитивы:** если в `src/shared/ui/` чего-то нет или макет расходится с китом/каноном — явный вопрос владельцу (если в макете ошибка относительно канона — пометка `ошибка макета / design error`).

### Шаг 2. Матрица обязательных состояний

Экран не считается готовым, если свёрстано только «обычное» (`default`) состояние. Для каждого задействованного элемента проверяются:

| Состояние | Правило реализации в StudioDesk |
|---|---|
| `default` | По токенам и компонентам `src/shared/ui/`. |
| `hover` / `active` | Уже заложены в варианты `Button`, `TableBody`, `Select`; не перебивать кастомными стилями. |
| `focus-visible` | Фокус не должен менять высоту контрола или вызывать скачок раскладки. |
| `disabled` | Ставится **только** тогда, когда это прямо предписано правилом продукта (или во время отправки запроса). Запрещено ставить `disabled` просто потому, что обработчик ещё не написан. |
| `loading` | На кнопке отправки формы или действия в модалке включается `loading={true}` у `Button`; на списках и страницах — состояние загрузки без мигания пустого состояния. |
| `empty` (данных ещё нет) | Фиксированный текст из канона темы (например, «No {plural} yet») и кнопка создания, где это предусмотрено потоком. |
| `no-results` (пусто по поиску/фильтру) | Фиксированный текст из канона темы («No {plural} found», подсказка и кнопка «Reset search» / «Reset filters»). |
| `error` (ошибка поля или действия) | Ошибки полей показываются у конкретного поля (`Field`) строго по `code` и `field` из таблицы `api-contract.md` / канона темы. Сырой серверный `message` пользователю никогда не выводится. Успех и общие ошибки действия — через `Toaster` или `Notice`. |
| Настольная и мобильная версия | Каждый экран проверяется на настольной ширине (`1280px`) и мобильной (`390×844`): таблицы со скроллом по горизонтали, поля форм в один столбец, кнопки модалок друг под другом. |
