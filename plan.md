## 1. Цель

Независимый сервис для йога- и танцевальных студий. Сейчас студии ведут расписание и записи в Telegram. Сервис даёт:

- многоразовое расписание;
- назначение тренеров на занятия;
- абонементы и списание посещений;
- запись клиентов;
- мини-сайт каждой студии;
- **главное отличие: встроенный управленческий учёт для владельца студии** (сколько заработала студия, сколько должна тренерам, расходы, прибыль).

Характер проекта: **зафиксировано** — скорее благотворительный, чем коммерческий. Цель — удобный бесплатный инструмент для нескольких знакомых студий (ориентир: 10–20 студий, десятки абонементов в каждой), а не захват рынка. Коммерческие вопросы — только если проект «взлетит».

## 3. Стек и инфраструктура

- **Зафиксировано.** Frontend — Next. Backend — Nest.
- **Зафиксировано.** База данных — собственный PostgreSQL, разворачиваем на своём сервере, **без Supabase**. Это значит: вход по телефону и коду, токены и авторизацию делаем сами в Nest.
- **Зафиксировано.** Изоляция студий (тенантов) — на уровне приложения по `studio_id`:
  - запрос без `studio_id` не обрабатывается;
  - если `studio_id` не связан с пользователем из токена, запрос отклоняется;
  - позже можно добавить RLS в PostgreSQL как второй слой защиты.
- **Предложение.** Единый общий механизм подстановки `studio_id` во все запросы (не ручные фильтры), плюс тесты на утечки между студиями. Схему таблиц строить так, чтобы RLS можно было добавить без переделки.
- **Предложение.** Один Nest-сервис (модульный монолит), не микросервисы. Контракт API — OpenAPI, из него типы для frontend.
- **Решено.** Локальная разработка: Docker Desktop, PostgreSQL в контейнере, см. `03-architecture/backend-structure.md`.
- **Решено.** Сервер и развёртывание: см. `03-architecture/deployment.md`. **Открыто:** резервные копии.
- **Открыто.** Канал доставки кода входа (SMS, Telegram, WhatsApp). Риски SMS обсудим при проектировании архитектуры.

## 5. Продукт: договорённости

### Три поверхности

- **Зафиксировано.** Админка платформы, админка студии, публичный сайт студии.
- **Зафиксировано.** Студия = тенант. Тенант публичного сайта определяется по хосту или поддомену.

### Мини-сайт студии

- **Зафиксировано.** Кастомизация уровня B: логотип, цвета, шрифт (через CSS-переменные), включение и порядок блоков на главной.
- **Зафиксировано.** Страницы залов, тренеров и видов занятий строятся автоматически из каталогов. Есть текстовые страницы About и Contacts. Расписание — блок на главной и отдельная страница.
- **Предложение.** SSR для SEO.

### Каталоги и локация

- **Зафиксировано.** Залы, тренеры и виды занятий — отдельные каталоги, создаются вместе со студией.
- **Зафиксировано.** Зал — главная сущность. Локация — адрес зала.

### Клиенты

- **Зафиксировано.** Аккаунт клиента свой у каждой студии.
- **Зафиксировано.** Вход по телефону и коду. После ввода кода клиент получает токен.
- **Зафиксировано.** Детские студии — частный случай, не целевой сегмент. Семейные и детские аккаунты не в первой версии.

### Модель занятий (обсуждено, детали не финальные)

- Общее у групповых занятий и записи к мастеру: в определённое время конкретный ресурс (тренер, зал) занят под услугу, к времени привязаны люди.
- Цепочка: **Ресурс** (тренер или зал, часы работы) → **Занятие** (время, ресурс, услуга, вместимость) → **Запись** (человек → занятие, статус, посещение).
- Тип занятия (групповое или индивидуальное) — свойство услуги. Первая версия начинается с групповых, но модель не должна мешать индивидуальным.
- Повторяющееся недельное расписание — шаблон, из которого занятия создаются на несколько недель вперёд. Исключения: отмена одного занятия, замена тренера.
- Запись и посещение — разные вещи (это позволяет списывать и при записи, и при посещении).
- Формат занятия: офлайн, онлайн или оба, с отдельной вместимостью на каждый формат.
- Вместимость и лист ожидания.

Все пункты ниже — **открыто**, обсуждаем дальше: шаблон недели и генерация занятий, замены и отмены, точный набор сущностей и связей.

### Абонементы

- **Зафиксировано.** Абонементы входят в первую версию; любая модель абонемента должна поддерживаться.
- **Зафиксировано.** Штрафов за неявку нет: «не пришёл» — просто статус.
- **Зафиксировано.** Отмена записи клиентом — обычная отмена.
- **Зафиксировано.** Заморозка абонемента (сейчас примерно раз в год на две недели; реальные условия студий нужно проверить) и продление владельцем студии (не тренером). Продлённый или замороженный абонемент не сгорает в доход.
- **Открыто.** Перенос занятия на другое время и перенос посещения: механика не проработана.
- **Открыто.** Три практики gmall, которые нужно описать подробно: абонемент тренера, промокод тренера, разовое занятие.

### Управленческий учёт

Подробности — `research/accounting-and-decisions.md`, раздел 3. Коротко:

- **Зафиксировано.** Продажа абонемента — предоплата. Доход студии возникает по посещению (цена абонемента / число занятий), по сгоранию остатка при истечении срока, позже по времени для подписок.
- **Зафиксировано.** Оплата тренера: процент от стоимости посещённого занятия, ставка за пришедшего, гарантия за месяц (может пересматриваться), для семинара — отдельное правило. Начисление возникает только при оплаченном посещении. Записи занятий начислений не создают.
- **Зафиксировано.** Семинар — отдельное событие со своей ценой и правилом оплаты.
- **Зафиксировано.** Аренда и прочие расходы учитываются, итог показывает прибыль. Сначала управленческий учёт, с местом для расширения до полного бухгалтерского.

### Онлайн-библиотека и курсы

- **Зафиксировано.** Не входят в первую версию; в модели закладывается место.
- Идея (из практики gmall): тренеры выкладывают записи занятий; доступ бесплатный, по абонементу или подписке, разовой покупкой, в составе курса. Абонемент в будущем может давать право доступа к библиотеке.

### Вне первой версии

Оплата через Stripe, штрафы, семейные и детские аккаунты, библиотека и курсы, несколько локаций сверх адреса зала.
