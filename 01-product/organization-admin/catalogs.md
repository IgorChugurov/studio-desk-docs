# Каталоги админки организации — единый механизм ресурсов

**Scope:** раздел Catalogs админки организации: все виды ресурсов организации (места, специалисты, оборудование, виды работ/услуг/занятий) на единой модели свойства-кубиков.
**Last verified:** 2026-10-27

## Эссе — что это

Catalogs — раздел админки организации. Его видят владелец и администратор (при условии, что раздел `catalogs` включён у организации). Верхняя строка вкладок не меняется: Catalogs остаётся одной вкладкой (`overview.md`).

Все элементы в `Catalogs` — и места (`Залы`, `Боксы`, `Кабинеты`, `Кресла`), и исполнители или оборудование (`Тренеры`, `Мастера`, `Механики`, `Аппараты`), и виды выполняемых работ, услуг или занятий (`Виды занятий`, `Услуги`, `Работы`) — устроены как **единая сущность Ресурс (`Resource`)**, управляемая списком видов ресурсов организации (`catalogConfig.resourceTypes` из `overview.md` и `../platform-admin/overview.md`).

Под верхней строкой вкладок вторая строка вкладок строится динамически из `catalogConfig.resourceTypes` организации в порядке их следования. Названия вкладок, кнопок и заголовков форм показываются на выбранном человеком языке интерфейса (`en`, `sk`, `uk`) из переводов, заданных в конфигурации организации. Вкладка Catalogs в верхней строке остаётся выделенной.

Хлебные крошки: название организации, Catalogs, затем название текущей вкладки во множественном числе. На добавлении в конце крошек «New {singular label}» (например, «New hall», «New trainer», «New class type», «New service»). На редактировании в конце название записи.

## Эссе — сущности

- **Вид ресурса (`ResourceType` в `catalogConfig.resourceTypes`):** определяет одну вкладку в `Catalogs`, её роль в расписании (`role: 'place' | 'resource' | 'offering'`) и набор включённых свойств («кубиков»).
- **Ресурс (`Resource`):** конкретная запись каталога, принадлежащая одному из видов ресурсов организации (`resourceTypeId`). Набор полей ресурса определяется кубиками, включёнными у его вида ресурса:
  - **База (есть у каждого ресурса любой роли):**
    - `Name` — обязательное название ресурса (например, «Большой зал», «Анна», «Подъёмник №1», «Хатха-йога», «Маникюр с покрытием», «Замена масла»).
  - **Кубик `geography` (всегда включён у вида с ролью `place` — место и якорь времени):**
    - `Type`: `ordinary` (обычный) или `virtual` (виртуальный). Можно выбрать при создании и потом поменять. У виртуального места адрес всегда «Virtual place», он ставится автоматически и не редактируется. Если тип сменили на виртуальный, адрес становится «Virtual place». Если тип сменили на обычный, адрес очищается и его нужно ввести заново.
    - `Address`: обязателен.
    - `Time zone`: из базы часовых поясов IANA, тот же элемент выбора, что в `Organization settings`. При создании по умолчанию стоит пояс организации. Время слотов в расписании хранится и считается по поясу этого места (`schedule.md`). Пояс места можно поменять: время слотов по часам места не меняется, реальные моменты пересчитываются; если из-за этого у другого ресурса со строгим правилом (`conflictMode = 'strict'`) возникает пересечение, сохранение отклоняется с указанием конфликтующего слота.
  - **Кубик `duration` (всегда включён у вида с ролью `offering` — вид работы, услуги или занятия):**
    - `Default duration` — обязательная норма длительности по умолчанию: **от 5 до 1440 минут, шаг 5 минут**. У новой записи поле сразу заполнено значением `60`. При выборе этого ресурса в форме слота расписания его `Default duration` автоматически подставляется в длительность слота, где её можно поменять (`schedule.md`).
  - **Кубик `showcase` (витрина):**
    - необязательные поля: `Description`, `Video link` (ссылка на YouTube или Vimeo, текст), `Instagram` (ссылка на Instagram), `TikTok` (ссылка на TikTok);
    - галерея файлов `images` на странице редактирования (`/files/resources/{resourceId}/{fileId}`).
  - **Кубик `person` (человек — доступ в систему):**
    - разрешает привязать этот ресурс к сотруднику с ролью `specialist` в разделе `Staff` (`overview.md`).
  - **Кубик `skills` (совместимость между ресурсами):**
    - необязательные списки связанных ресурсов других видов (`relatedResourceIds`), у которых тоже включён кубик `skills` (например, какие мастера или посты выполняют данный вид работы `offering`).

- **Связь между ресурсами (`resource_relation`).**
  Симметричная связь много-ко-многим между ресурсами одной организации, у видов которых включён кубик `skills`. Задаётся на карточке любого из двух связанных видов ресурсов; это одна и та же связь. В форме слота расписания (`schedule.md`) она служит фильтром-подсказкой при выборе ресурсов. Уже стоящие в расписании слоты она не ограничивает, снять её можно всегда.

- **Файлы (`images`)** ресурса (`../../03-architecture/files.md`).
  У каждого файла есть индекс (`0, 1, 2...`). В ответе они приходят в поле `images`, отсортированные по индексу. Картинка показывается картинкой, видеофайл — тегом `video`. Публичный адрес единый для всех ресурсов:
  `/files/resources/{resourceId}/{fileId}` (плюс расширение `.jpg`, `.png`, `.webp`, `.gif`, `.mp4`, `.webm`).
  Ссылка на YouTube или Vimeo в `images` не входит.

Индексы файлов:
- Новый файл получает индекс, равный текущему числу файлов этого ресурса (первый файл получает `0`). Несколько файлов за раз получают индексы подряд в порядке добавления.
- Удаление файла переписывает индексы оставшихся подряд с нуля.
- Перетаскивание меняет порядок на странице и вызывает отдельный запрос обновления индексов. Сохранение полей ресурса индексы не меняет.
- Галерея доступна только на странице редактирования уже сохранённого ресурса, если у его вида включён кубик `showcase`. На странице создания галереи нет.

## Эссе — страницы

Для каждой вкладки из `catalogConfig.resourceTypes`:
- **Список ресурсов этого вида** — корень вкладки. Кнопки «Back» нет.
- **Добавление ресурса** — страница внутри вкладки.
- **Редактирование ресурса** — страница внутри вкладки. Здесь же галерея (если включён `showcase`) и внизу недельная сетка расписания этого ресурса (для ресурсов ролей `place` и `resource`).

## Эссе — потоки по шагам

Тексты в каноне даются на английском как исходные. В заголовках и кнопках подставляется название вида ресурса из конфигурации организации на текущем языке интерфейса (`{Plural}`, `{Singular}`, `{singular}`). Внешний вид списков и форм: `../../02-design/flow-design.md`. Сообщения о результате и ошибках действия — как в `overview.md`.

### Поток 1. Список ресурсов (на любой вкладке `Catalogs`)

Строка действий: слева поиск, справа кнопка добавления («Add {singular}», например «Add hall», «Add trainer», «Add class type», «Add service»). Поиск — подстрока названия без учёта регистра. Таблица.
- **Столбцы:**
  - `Name` (всегда);
  - `Address` (если у вида ресурса включён кубик `geography`);
  - `Default duration` (если у вида ресурса включён кубик `duration`);
  - последний столбец — меню ⋮ с «Edit». «Back» нет.
- **Пусто, когда записей нет:** «No {plural} yet» с кнопкой «Add {singular}».
- **Пусто по поиску:** «No {plural} found», подсказка «Change the search term to find what you're looking for.», кнопка «Reset search» (фиксировано).

### Поток 2. Добавление ресурса

Поля формы собираются по включённым кубикам вида ресурса:
- всегда: «Name» (обязательно);
- если включён `geography` (`role = 'place'`): «Type» (`Ordinary` / `Virtual`, по умолчанию `Ordinary`), «Address» (обязательно; при `Virtual` автоматически «Virtual place» только для чтения; при возврате на `Ordinary` очищается), «Time zone» (обязательно, по умолчанию пояс организации);
- если включён `duration` (`role = 'offering'`): «Default duration» (минуты, обязательно, от `5` до `1440` с шагом `5`, по умолчанию заполнено `60`);
- если включён `showcase`: «Description», «Video link» (YouTube или Vimeo), «Instagram», «TikTok» (все необязательны);
- если включён `skills`: мультиселекты связанных ресурсов других видов, у которых включён `skills` (необязательно).
Кнопки «Back» и «Save». «Back» возвращает в список без сохранения. Галереи нет.
- Ошибки у поля (фиксировано):
  - «Enter a name»;
  - «Enter an address»;
  - «Enter a duration from 5 to 1440 minutes in steps of 5»;
  - «Enter a YouTube or Vimeo link»;
  - «Enter an Instagram link»;
  - «Enter a TikTok link».
- Успех: возврат в список, сообщение «{Singular} added».

### Поток 3. Редактирование ресурса

Те же поля, заполнены. Кнопки «Back» и «Update». «Back» возвращает в список без сохранения.
- Если у вида ресурса включён `showcase`, ниже полей — галерея `images` по индексу. Кнопка «Add file» (фиксировано). Удаление файла через окно «Remove file?», текст «This file will be removed. You can add it again at any time», кнопки «Remove» и «Cancel» (фиксировано), успех «File removed» (фиксировано). Перетаскивание вызывает отдельный запрос обновления индексов.
- Для ресурсов с ролями `place` и `resource` под галереей отображается расписание этого ресурса: компонент из `schedule.md`, отфильтрованный по этому ресурсу (недельная сетка и действия со слотами).
- Успех сохранения полей: возврат в список, сообщение «{Singular} updated».

## Агент — правила

- Все вкладки внутри `Catalogs` работают на единой сущности `Resource` и строятся динамически из `catalogConfig.resourceTypes` организации на языке интерфейса человека (`en`, `sk`, `uk`). Отдельной таблицы или отдельного механизма для видов занятий/услуг нет: вид работ/услуг — это вид ресурса с ролью `offering` и кубиком `duration`.
- Поля формы ресурса определяются кубиками его `resourceType`: `geography` (всегда у `role = 'place'`), `duration` (всегда у `role = 'offering'`, от `5` до `1440` минут с шагом `5`, у нового `60`), `showcase`, `person`, `skills`.
- У ресурса с `geography` тип (`ordinary` или `virtual`) можно выбрать при создании и менять позже. У виртуального места адрес всегда «Virtual place» только для чтения; смена на `ordinary` очищает адрес. Пояс по умолчанию — пояс организации. При смене пояса время слотов по часам места не меняется; если возникает пересечение у ресурса со строгим правилом (`strict`), сохранение отклоняется с указанием слота.
- Связь между ресурсами (`resource_relation`) симметрична для видов с кубиком `skills`, правится с любой из сторон и служит только фильтром выбора в форме слота расписания; уже стоящие слоты она не ограничивает.
- Вместимость (`group / one_person`, `places`) и формат (`offline / online`) не хранятся в каталоге — они задаются на слоте в расписании (`schedule.md`).
- Галерея доступна только на редактировании уже сохранённого ресурса с кубиком `showcase`. Публичный путь всех файлов каталога — `/files/resources/{resourceId}/{fileId}`.
- Менять документ только после явного согласия владельца.

## Агент — чеклист приёмки

- [ ] Вкладка Catalogs остаётся одной в верхней строке
- [ ] Вторая строка вкладок строится динамически из `catalogConfig.resourceTypes` организации на текущем языке интерфейса
- [ ] Места (`place`), специалисты/оборудование (`resource`) и виды работ/услуг (`offering`) работают через единую модель `Resource`
- [ ] Форма ресурса включает поля в соответствии с кубиками его вида (`geography`, `duration`, `showcase`, `skills`)
- [ ] У места (`role = 'place'`) тип `ordinary / virtual`, адрес («Virtual place» для виртуального) и часовой пояс IANA с проверкой пересечений при смене пояса
- [ ] У вида работы/услуги (`role = 'offering'`, кубик `duration`) длительность по умолчанию от 5 до 1440 минут с шагом 5 (у нового 60)
- [ ] Симметричная связь `resource_relation` работает между видами ресурсов с кубиком `skills`
- [ ] На редактировании ресурса (`place` и `resource`) внизу отображается его недельная сетка расписания
- [ ] Галерея файлов `/files/resources/{resourceId}/{fileId}` на редактировании с сортировкой и перетаскиванием по индексу
- [ ] Мобильная версия каждого экрана
